# Migrating to v0.114.x

0.114.0 brings the library in line with Carbon v11. Token names, type
style names and token values now match the v11 Figma kit. It also
replaces flatpickr with a built-in calendar and removes `light` in
favor of `Layer`.

## Find what to change

Run this from your app's root. Each hit is a line to change.

```sh
# v10 color and type token names
rg -n -e '--cds-(ui-0|ui-background|text-0|icon-0|link-0|interactive-0|inverse-|support-0|danger|disabled-0|hover-|active-|selected-|visited-link|decorative-01|skeleton-0|overlay-01|brand-0)' \
  -e '(body-short|body-long|productive-heading|expressive-heading|expressive-paragraph|caption)-0' \
  -e '(^|[^-]|[^d]-)(quotation|display)-0[1-4]' src

# Props, APIs and private variables that changed
rg -n -e '\blight\b' -e 'flatpickr' -e 'selectOnFocus' -e 'bind:calendar' -e 'layer-03' \
  -e '<SearchMenu\b' src

# Test queries that need a new role or name
rg -n -e 'Role\("alert"' -e 'name: "menu"' -e 'Title\("Clear filter"' \
  -e 'Active, Page' -e 'Select Page number' .
```

Some components changed their look or defaults but need no code
change. To review them, search for them too:

```sh
rg -n -e '<(TooltipIcon|UserAvatar|BigNumber|InterstitialScreen|TagSet|ActionSet)\b' \
  -e 'leaveDelayMs' -e '\bg80\b' src
```

`svelte-check` also helps. The `light` prop, `flatpickrProps`,
`selectOnFocus`, v10 `type` values and v10 Theme token keys are all
type errors now. CSS reads of v10 tokens are not, so the `rg` search
is the only way to find those.

## 1. Color tokens

all.css no longer declares v10 names. A `var(--cds-ui-01)` resolves to
nothing, and an override of `--cds-interactive-01` changes nothing. No
error appears, so search for them.

Rename `--cds-<v10>` in your CSS and `"<v10>"` keys in the Theme
`tokens` prop.

```css
/* before */
.card {
  background: var(--cds-ui-01);
  border: 1px solid var(--cds-ui-03);
  color: var(--cds-text-01);
}

/* after */
.card {
  background: var(--cds-layer-01);
  border: 1px solid var(--cds-border-subtle-01);
  color: var(--cds-text-primary);
}
```

```svelte
<!-- before -->
<Theme tokens={{ "interactive-01": "#d02670", "text-01": "#fff" }} />

<!-- after -->
<Theme tokens={{ "button-primary": "#d02670", "text-primary": "#fff" }} />
```

Carbon split some v10 tokens. Pick the v11 token by what the color
paints: borders take a `border-*` name, fills take `layer-*` or
`background-*`, text takes `text-*`, and icons take `icon-*`.

If your component sits on a surface that can change, read the
contextual token without a number (`layer`, `field`,
`border-subtle`). A `Layer` re-points those, so the component follows
its surface. See [3. Layer](#3-replace-light-with-layer).

A few notes:

- `text-placeholder` keeps `text-helper`'s value. v11's placeholder
  gray is 2.6:1 on a white field, below WCAG AA. If you overrode
  `text-03`, set `text-placeholder` to the same value.
- The Theme `tokens` prop now only accepts names all.css declares, and
  your editor completes them. Each key is set as `--cds-{key}`. To set
  a name outside the list, cast the object:

  ```svelte
  <script lang="ts">
    import { Theme } from "carbon-components-svelte";
    import type { ComponentProps } from "svelte";

    const tokens = {
      "button-primary": "#d02670",
      "brand-accent": "#d02670",
    } as ComponentProps<Theme>["tokens"];
  </script>

  <Theme {tokens} />
  ```

- The new `carbon-components-svelte/tokens` export lists every token
  with its value per theme, if you need them in JavaScript.
- Every stylesheet now declares its theme's tokens on `:root`, so
  your CSS can read `var(--cds-…)` with white.css, g10.css and the
  other single-theme files too. Before, only all.css declared the
  full set
  ([#5099](https://github.com/carbon-design-system/carbon-components-svelte/pull/5099)).
  The components in those files still compile most values in. Only
  the contextual tokens (`layer`, `field`, `border-subtle` and
  similar) are custom properties there, so that `Layer` works.

## 2. Type styles

The same names apply to the `Text` and `Heading` `type` prop, the
`.bx--type-*` classes and the custom properties
(`--cds-body-short-01-font-size` is now
`--cds-body-compact-01-font-size`).

```svelte
<!-- before -->
<Text type="body-short-01">Saved</Text>
<Heading type="productive-heading-03">Settings</Heading>
<p class="bx--type-caption-01">Updated today</p>

<!-- after -->
<Text type="body-compact-01">Saved</Text>
<Heading type="heading-03">Settings</Heading>
<p class="bx--type-label-01">Updated today</p>
```

| v10 | v11 |
| :--- | :--- |
| caption-01, caption-02 | label-01, label-02 |
| body-short-01, -02 | body-compact-01, -02 |
| body-long-01, -02 | body-01, body-02 |
| productive-heading-01, -02 | heading-compact-01, -02 |
| productive-heading-03 to -07 | heading-03 to heading-07 |
| expressive-heading-01, -02 | heading-01, heading-02 |
| expressive-heading-03 to -06 | fluid-heading-03 to -06 |
| expressive-paragraph-01 | fluid-paragraph-01 |
| quotation-01, -02 | fluid-quotation-01, -02 |
| display-01 to -04 | fluid-display-01 to -04 |

`label-*`, `helper-text-*`, `code-*`, `heading-01` and `heading-02`
keep their names. `legal-01` and `legal-02` are new.

Two styles look a little different:

- `caption-02` had 0.32px letter spacing. `label-02` has 0.16px.
- `expressive-heading-01` had a 1.25 line height. `heading-01` has
  1.42857.

The fluid styles now match `@carbon/type` at every breakpoint
([#5020](https://github.com/carbon-design-system/carbon-components-svelte/pull/5020)).
`fluid-heading-04` reaches 2rem at `xlg`, not at `max`.
`fluid-paragraph-01` drops v10's 1.29 line height at `lg`, and
`fluid-display-04` line heights move by 0.01.

`Text` still defaults to the same style. Its default is now called
`body-01`.

## 3. Replace `light` with Layer

v11 removed `light`. `Layer` is new in 0.114. It re-points the
contextual tokens, so every component inside it takes the next
surface. Fields, tiles and menus all follow.

```svelte
<!-- before -->
<TextInput light labelText="Workspace name" />

<!-- after -->
<script>
  import { Layer, TextInput } from "carbon-components-svelte";
</script>

<Layer>
  <TextInput labelText="Workspace name" />
</Layer>
```

## 4. DatePicker

flatpickr is gone. The calendar is built in, each option is a prop,
and the markup uses Carbon class names. If you only pass `value`,
`datePickerType`, `dateFormat`, `minDate` or `maxDate`, your app needs
no change. Tests that query the calendar still do; see
[CSS and tests](#css-and-tests).

The calendar looks the same. Each pair below shows flatpickr in 0.113
on the left and the built-in calendar on the right:

<img width="800" alt="flatpickr and the built-in calendar side by side: single, range, multiple, week, week numbers and month" src="https://raw.githubusercontent.com/carbon-design-system/carbon-components-svelte/d49c49c449b23ea9938f5e250e7d273d4f146731/4158/dp-sheet-1.png">

### Options

Move each `flatpickrProps` key to its prop:

| flatpickrProps | Prop |
| :--- | :--- |
| `minDate`, `maxDate`, `allowInput`, `closeOnSelect`, `conjunction`, `inline` | same name |
| `showMonths` | `months` |
| `shorthandCurrentMonth` | `monthLabel="short"` |
| `positionElement` | `anchor` |
| `position` | `align` and `direction` (for a portalled calendar; an in-place calendar opens below the field) |
| `allowInvalidPreload` | `keepOutOfRangeValue` |
| `ignoredFocusElements` | `keepOpenFor` |
| `disable` | `disabledDates` |
| `enable` | `enabledDates` |
| `altInput`, `altFormat` | `displayFormat` |
| `defaultDate` | `value` or `selectedDates` |

```svelte
<!-- before -->
<DatePicker
  datePickerType="single"
  flatpickrProps={{ showMonths: 2, disable: [isWeekend] }}
/>

<!-- after -->
<DatePicker datePickerType="single" months={2} disabledDates={[isWeekend]} />
```

### Hooks and plugins

- Replace `onDayCreate` with `dayClass` or `dayDescription`.
- Replace the other hooks with events: `on:change`, `on:open`,
  `on:close`, `on:view`, `on:error`.
- Replace the range, monthSelect and weekSelect plugins with
  `datePickerType="range"`, `"month"` or `"week"`. `"quarter"` is new.
  Other plugins are not supported.

### Locales

A language tag needs no import:

```svelte
<!-- before -->
<script>
  import { German } from "flatpickr/dist/l10n/de";
</script>
<DatePicker locale={German} />

<!-- after -->
<DatePicker locale="de" />
```

Month and weekday names then come from the browser's `Intl` data, so
they can differ slightly between browsers. A locale object still
works when you need exact strings. If you keep importing from
`flatpickr/dist/l10n`, add `flatpickr` to your own dependencies; the
package no longer installs it.

### `bind:calendar`

`bind:calendar` is a `DatePickerCalendar`, not the flatpickr instance:

```svelte
<script>
  let calendar;
</script>

<DatePicker datePickerType="single" bind:calendar>…</DatePicker>
<Button on:click={() => calendar.showMonth(new Date(2027, 0, 1))}>January</Button>
```

| flatpickr instance | DatePickerCalendar |
| :--- | :--- |
| `open()`, `close()` | `open()`, `close()`, or `bind:open` |
| `isOpen` | `isOpen` |
| `jumpToDate(date)` | `showMonth(date)` |
| `currentYear`, `currentMonth` | `view` (a Date) |
| `selectedDates` | `selectedDates` (read-only) |
| `setDate(...)` | `bind:selectedDates` or `bind:value` |

The calendar has no time picker; pair it with `TimePicker`. The native
mobile date input and the month dropdown are not available either.

## 8. Tests

These are fixes, not API changes, but tests can notice them.

- **ARIA attributes moved.** In about 30 components, a consumer
  `aria-label`, `aria-labelledby` or `aria-describedby` now goes on
  the focusable or role element, not a wrapper. A consumer
  `aria-describedby` now joins the built-in helper and error ids
  instead of replacing them. `Table` replaced them on purpose before;
  it now joins them too. Update snapshots and attribute queries.
- **Read-only number fields are text inputs.** A read-only NumberInput
  or `type="number"` TextInput has the role `textbox`. Change
  `getByRole("spinbutton")` to `getByRole("textbox")`.
- **Read-only Slider and RangeSlider show text.** The inputs are
  hidden, so they fire no `focus` or `blur`, a label click focuses
  nothing, and the keyboard can't reach the value.
- **ComboBox needs focus for input.** An `input` event on an unfocused
  ComboBox no longer opens the menu. Focus the input first, or use
  `user.type`, which focuses it for you.
- **Select ignores a value it doesn't list.** A script or
  `fireEvent.change` that sets a value with no matching option no
  longer changes `selected` or fires `update`. Before, `selected`
  became `""`. Use a value the select lists ([#5108](https://github.com/carbon-design-system/carbon-components-svelte/pull/5108)).
- **A list box marks only the cursor option.** A selected option no
  longer has `bx--list-box__menu-item--highlighted`; it keeps
  `--active`. Update selectors and CSS that read it ([#4945](https://github.com/carbon-design-system/carbon-components-svelte/pull/4945)).
- **An active Loading overlay is a dialog.** It takes focus, keeps it
  on Tab, and gives it back when loading stops. Tests can't focus a
  control behind an active overlay ([#4924](https://github.com/carbon-design-system/carbon-components-svelte/pull/4924)).
- **ExpandableTile finds links and buttons itself.**
  `hasInteractiveContent` now defaults to `undefined`. After mount, a
  tile with interactive content switches to a `div` and a chevron
  button, as if you had set `true`. Set `false` to keep the old
  `button` ([#4963](https://github.com/carbon-design-system/carbon-components-svelte/pull/4963)).
- **TooltipDefinition opens on Enter and Space,** and its trigger has
  `aria-expanded` and `aria-controls` ([#4971](https://github.com/carbon-design-system/carbon-components-svelte/pull/4971)).
- **ClickableTile and HeaderPanelLink without `href`** are buttons now
  (`role="button"` on the tile, a `button` element for the link).
- **DatePicker** has new roles and classes; see
  [CSS and tests](#css-and-tests).
- **Right-to-left pages mirror.** Under `dir="rtl"`, the UI Shell,
  menus and submenus, list boxes, TreeView, Tabs, Pagination,
  Breadcrumb, Button, the text fields, Select, DatePicker and Slider
  flip their layout, and forward and back icons mirror, Card's
  included. Left and Right swap in Slider, RangeSlider, TreeView,
  Tabs, Carousel, ContentSwitcher, ToggleButtonGroup,
  ProgressIndicator, TagSet, TagInput, PinCodeInput, the header
  menubar and the DatePicker calendar, as they do in a native range
  input. SideNav and Splitter resize from the inline end. Tooltip and
  popover `align="start"` and `"end"` swap sides; `left` and `right`
  stay physical. A sign in BigNumber and the "+N" in TagSet and
  UserAvatarGroup keep their place. CodeSnippet code stays left to
  right. Left-to-right pages are unchanged
  ([#5013](https://github.com/carbon-design-system/carbon-components-svelte/pull/5013),
  [#5014](https://github.com/carbon-design-system/carbon-components-svelte/pull/5014),
  [#5015](https://github.com/carbon-design-system/carbon-components-svelte/pull/5015),
  [#5031](https://github.com/carbon-design-system/carbon-components-svelte/pull/5031),
  [#5166](https://github.com/carbon-design-system/carbon-components-svelte/pull/5166),
  [#5171](https://github.com/carbon-design-system/carbon-components-svelte/pull/5171),
  [#5175](https://github.com/carbon-design-system/carbon-components-svelte/pull/5175)).
  See the
  [right-to-left guide](https://svelte.carbondesignsystem.com/right-to-left).
- **The nearest `dir` wins.** A plain `dir="ltr"` inside an RTL page
  or LayoutDirection lays out left to right, reads the arrow keys left
  to right, and opens its portalled menus, tooltips and calendar left
  to right. Slider and RangeSlider place their thumbs by the nearest
  `dir` in the styles, so a server render under a plain `dir="rtl"`
  is mirrored before it hydrates. The library's `[dir="rtl"]` rules
  keep their selectors and weight, but each value now reads the
  nearest `dir`. If your CSS overrides one, it still wins. It also
  still matches inside a `dir="ltr"` region of an RTL page, where the
  library's rule now switches back. Every element with a `dir` sets
  private direction variables (`--ccs-inline-sign`, `--ccs-mirror-rtl`,
  `--ccs-rtl`, `--ccs-ltr`) for these rules; don't set them yourself
  ([#5069](https://github.com/carbon-design-system/carbon-components-svelte/pull/5069),
  [#5070](https://github.com/carbon-design-system/carbon-components-svelte/pull/5070),
  [#5072](https://github.com/carbon-design-system/carbon-components-svelte/pull/5072),
  [#5073](https://github.com/carbon-design-system/carbon-components-svelte/pull/5073)).
- **Slider positions are `calc()` values.** A thumb at 20% has
  `left: calc(50% + (20% - 50%) * var(--ccs-slider-sign, 1))`, not
  `left: 20%`, and the fill's `transform` gains a mirror step. Check
  the thumb's box, not its `style`.
- **CopyInput sets `dir="auto"`** on its input, so a URL keeps its
  order in a right-to-left page. Pass `dir` to override it.
- **ClickableTile is `position: relative`**, as in v11. Content you
  position absolutely inside a tile now anchors to the tile.
- **Notifications are `status`, not `alert`.** See
  [11. Notifications](#11-notifications).
- **A notification title always has an id.** A
  NotificationActionButton's `aria-describedby` points at it, so
  screen readers read the title with the action.
- **NotificationQueue is a landmark.** Query it with
  `getByRole("region", { name: "Notifications" })`.
- **The modal heading is an `h2`.** Heading queries for the modal
  title need `level: 2`, not `level: 3`.
- **OverflowMenu's trigger is named "Options".** Its default name was
  "menu". `iconDescription` now sets the name and the tooltip.
- **PaginationNav pages are named "Page 3",** not "Active, Page 3".
  `aria-current="page"` marks the current page. The overflow select
  is "Select page number", not "Select Page number". Set them with
  `pageText` and `pageSelectLabelText`
  ([#4800](https://github.com/carbon-design-system/carbon-components-svelte/pull/4800)).
- **A few more names changed.** The DataTableSkeleton toolbar is no
  longer a `region`. HeaderSearch names its button and results list
  with `labelText` ("Search" by default), and its icon has no
  `title`. StructuredList's selection column header no longer holds a
  hidden "Select row" ([#4800](https://github.com/carbon-design-system/carbon-components-svelte/pull/4800)).
- **ContextMenu opened from the keyboard focuses its first option.**
  Shift+F10 or the context menu key now puts focus on the first
  enabled option. A right-click still focuses the menu
  ([#4807](https://github.com/carbon-design-system/carbon-components-svelte/pull/4807)).
- **A filterable Tag's close button has no `title`.** It shows a
  tooltip instead. Query it by role and name, not by title.
- **Icon tooltips close 100ms after the pointer leaves.** Wait for
  the tooltip to hide, or set `leaveDelayMs={0}`. See
  [14. Tooltips](#14-tooltips).
- **Returned focus shows no tooltip.** When a Modal, menu or
  HeaderAction panel closes and gives focus back to an icon button,
  the button's tooltip stays closed.
- **Escape hides a tooltip first.** The icon tooltips of icon-only
  Button, CopyButton, Switch, Tab, ToggleButton, PasswordInput,
  HeaderAction and FileUploaderButton, and the copy feedback of
  CopyButton and CodeSnippet, now close on Escape. The key stops
  there, so a Modal around them needs a second Escape. With a
  HeaderAction panel open, one press closes both
  ([#4923](https://github.com/carbon-design-system/carbon-components-svelte/pull/4923),
  [#5006](https://github.com/carbon-design-system/carbon-components-svelte/pull/5006)).
- **TextArea announces its limit after 1s**, as TextInput does. Wait
  or advance timers before you check the live region
  ([#5018](https://github.com/carbon-design-system/carbon-components-svelte/pull/5018)).
- **BigNumber percentages are not abbreviated**, and the percent sign
  takes the locale's place. Text that matched "1.2K%" is now
  "1,234.5%". See [16. Component updates](#bignumber).
- **The InterstitialScreen title is an `h1` or `h2`.** See
  [16. Component updates](#interstitialscreen).
- **ActionSet warns** with `console.warn` when its actions break
  v11's rules. Tests that fail on console warnings catch it. See
  [16. Component updates](#actionset).
- **Markup snapshots change.** DataTable and `TableCell` cells have
  the class `bx--table-cell` ([#4149](https://github.com/carbon-design-system/carbon-components-svelte/pull/4149)). With an `id`, a
  notification's title and subtitle ids are `{id}-title` and
  `{id}-subtitle`, and the HeaderSwitcher and ProfileMenu menu id is
  `{id}-menu` ([#5089](https://github.com/carbon-design-system/carbon-components-svelte/pull/5089)). A filterable MultiSelect's clear button no
  longer renders `open`, and ContextMenuOption no longer renders
  `indented` ([#5113](https://github.com/carbon-design-system/carbon-components-svelte/pull/5113)). A TreeView leaf wraps its name in a span
  ([#4716](https://github.com/carbon-design-system/carbon-components-svelte/pull/4716)).
- **Server markup changes.** Under Svelte 3 and 4, the server writes
  boolean ARIA states as `aria-hidden="true"`, not as a bare
  `aria-hidden` ([#5084](https://github.com/carbon-design-system/carbon-components-svelte/pull/5084)). Carousel, InterstitialScreen,
  UserAvatarGroup and a one-line TagSet render their first state on
  the server: only the current slide or step shows, and the "+N"
  avatar is there before hydration
  ([#5082](https://github.com/carbon-design-system/carbon-components-svelte/pull/5082), [#5086](https://github.com/carbon-design-system/carbon-components-svelte/pull/5086), [#5087](https://github.com/carbon-design-system/carbon-components-svelte/pull/5087), [#5097](https://github.com/carbon-design-system/carbon-components-svelte/pull/5097), [#5098](https://github.com/carbon-design-system/carbon-components-svelte/pull/5098)).
  Tests that compare server HTML need new snapshots.

## 10. Modals

Three things change in `Modal` and `ComposedModal`.

### Modals start a Layer

The modal now works as in v11: it sits on the first surface, and its
body is a `Layer`. Everything in the body moves up one level by
itself:

- Tiles, DataTable rows and Accordions no longer blend into the modal
  background.
- A `<Layer>` inside a modal steps up one more level.
- Field backgrounds look the same as before, except in Gray 80, where
  they step down to #393939 (see [Gray 80](#gray-80)). In Gray 80, 90

  slightly, to match v11.

If you styled fields inside modals with your own CSS, check it. The

Menus that open from a modal (Dropdown, ComboBox, MultiSelect,

first surface, as before.

### Transactional modals stay open on an outside click

As in v11, a click outside a modal closes it only when the modal is
passive. A Modal with `passiveModal`, or a ComposedModal without a
`ModalFooter`, still closes. Any other modal stays open, so the user
must pick an action.


### The heading is an `h2`

The Modal heading and the ModalHeader `title` render as `h2`, not
`h3`, as in v11. Update CSS that targets `h3` and tests that query a
level 3 heading.

## 11. Notifications

### Notifications default to `role="status"`

`InlineNotification` and `ToastNotification` now default to
`role="status"`, as in v11. Screen readers announce them politely.
Before, every notification was an `alert`, even a success.

Update tests that query the role:

```js
// before
screen.getByRole("alert");

// after
screen.getByRole("status");
```

For an urgent message, such as an error the user must act on, pass
`role="alert"`. The status icon now has a name, such as "Warning".
Set it with `statusIconDescription`.

### Toast actions are tertiary buttons

A `NotificationActionButton` inside a `ToastNotification` now renders
as a small tertiary button, as in v11. Before, it was the ghost
button from InlineNotification, and its label was hard to read on a
dark toast. This applies anywhere in the toast, the default slot
included. Its class is now `bx--toast-notification__action-button`.

Toasts also have an `actions` slot, as InlineNotification does. It
puts the action under the text:

```svelte
<!-- before -->
<ToastNotification title="Upload failed">
  <NotificationActionButton>Retry</NotificationActionButton>
</ToastNotification>

<!-- after -->
<ToastNotification title="Upload failed">
  <svelte:fragment slot="actions">
    <NotificationActionButton>Retry</NotificationActionButton>
  </svelte:fragment>
</ToastNotification>
```

### A notification with an action ignores `timeout`

An InlineNotification with an action in its `actions` slot no longer
closes after `timeout`. As in v11, a notification with an action stays
until the user acts on it or closes it, so a timer can't remove the
action before a keyboard or screen reader user reaches it. An
`actionable` notification and a toast with an `actions` slot work the
same way.

If you need it gone after a delay, set `open` to `false` yourself, or
move the action out of the notification.

### NotificationQueue

The queue is now a landmark named "Notifications". Set `labelText` to
rename it. Every toast's timer pauses while the pointer or focus is in
the queue, and resumes with the time it had left. Press F6 to move
focus to the newest toast and back.

## 12. Sizes

### Search defaults to 40px

A `Search` without `size` is now 40px tall (`lg`), like the other
fields and v11. Before, it was 48px. `ToolbarSearch` stays 48px. To
keep the old height, set `size="xl"`:

```svelte
<Search size="xl" />
```

### Carbon v11 size names

You don't need to change code. Components now accept Carbon v11's
size names next to their own, so code ported from Carbon React gets
the right height. Your existing names keep their meaning
([#4974](https://github.com/carbon-design-system/carbon-components-svelte/pull/4974),
[#5019](https://github.com/carbon-design-system/carbon-components-svelte/pull/5019)).

| Component | v11 names you can use |
| :--- | :--- |
| Button, FileUploader | `sm` (`small`), `md` (`field`), `2xl` (`xl`) |
| TextInput, PasswordInput, Select, NumberInput, DatePickerInput, TimePicker, Form, InputGroup | `md` (40px default), `lg` (`xl`) |
| PinCodeInput | `md` (`default`), `lg` (`xl`) |
| ComboBox, Dropdown, MultiSelect | `md` (40px default) |
| Search, SearchMenu | `md` (`lg`, 40px) |
| Accordion, ContentSwitcher, OverflowMenu | `md` (default), `lg` (`xl`) |
| Tag, Toggle | `md` (`default`) |
| FileUploaderItem, FileDownloadItem | `sm` (`small`), `md` (`field`), `lg` (`default`) |
| Modal, ComposedModal | `md` (default width) |
| TreeView | `xs` (`compact`), `sm` (`default`) |
| DataTable | `xs`, `sm`, `md`, `lg`, `xl` (compact to tall) |
| DataTable Toolbar | `lg` (`default`) |
| ProgressBar | `small` (`sm`), `big` (`md`) |

Two v11 names already mean something else here, and keep that
meaning:

- Button's `lg` is 64px and `xl` is 80px. For v11's 48px `lg`, use
  `default`. For v11's 64px `xl`, use `lg`.
- Search's `lg` is 40px. For v11's 48px `lg`, use `xl`.

`Form` now has a `size` that its fields inherit, as does the new
`InputGroup`. An explicit `md` on a field wins over it.

## 13. Tags and tiles

Tags no longer have an outer margin, as in v11. Space them with their
container: `TagSet` spaces its tags for you, or use a horizontal
`Stack`. `gap={3}` gives the 8px v11 uses. The `inline` prop has no
effect and is deprecated.

```svelte
<!-- before: each tag brought its own margin -->
<Tag>IBM Cloud</Tag>
<Tag type="blue">Machine learning</Tag>

<!-- after -->
<Stack orientation="horizontal" gap={3}>
  <Tag>IBM Cloud</Tag>
  <Tag type="blue">Machine learning</Tag>
</Stack>
```

Tags are also capped at 208px wide, as in v11. A longer label
truncates and shows in full in a tooltip. Set `maxWidth` to change
the cap.

`SelectableTile` shows the v11 checkbox: an empty box until the tile
is selected, then a checked box. Before, a round checkmark showed only
when selected. Expect new visual snapshots.

## 14. Tooltips

Icon tooltips now work as v11's IconButton does. This covers
TooltipIcon, icon-only Buttons, CopyButton, OverflowMenu,
PasswordInput, ToggleButton, HeaderAction and FileUploaderButton
([#5012](https://github.com/carbon-design-system/carbon-components-svelte/pull/5012)).

- They close 100ms after the pointer leaves. In 0.113, `TooltipIcon`
  and portal tooltips waited 300ms, and an inline icon-only Button's
  tooltip closed at once. To change the delay, set `leaveDelayMs` on
  a TooltipIcon or on a `TooltipGroup` around the icons.
- The pointer can move onto the tooltip, portal or inline, and the
  tooltip stays while the pointer is on it. Tooltips no longer set
  `pointer-events: none`.
- A tooltip often covers a neighbor, as in a row of buttons. When the
  pointer reaches that part, the tooltip closes at once, so the next
  click presses the neighbor. A click on the rest of the tooltip does
  nothing.
- Focus that a component gives back, such as a closing Modal or menu,
  no longer shows the tooltip. Your own focus or hover still does.

`Tooltip` and `TooltipDefinition` keep their 300ms leave delay. The
pointer can now rest on an inline TooltipDefinition too.

## 15. Menus and tooltips in a clipping box

A box with `overflow` other than `visible`, such as a DataTable, a
scrolling panel or an `overflow: hidden` card, used to cut off a menu
or tooltip that opened in it. Now, when such a box would cut one off,
it moves to a portal for that open. One that fits stays in place, so
its markup doesn't change
([#4712](https://github.com/carbon-design-system/carbon-components-svelte/pull/4712),
[#4713](https://github.com/carbon-design-system/carbon-components-svelte/pull/4713),
[#4714](https://github.com/carbon-design-system/carbon-components-svelte/pull/4714),
[#5096](https://github.com/carbon-design-system/carbon-components-svelte/pull/5096)).

| Component | Prop |
| :--- | :--- |
| Dropdown, ComboBox, MultiSelect, OverflowMenu, DatePicker | `portalMenu` |
| Tooltip, TooltipIcon, TooltipDefinition, icon-only Button, PasswordInput, Toggletip | `portalTooltip` |
| Popover | `portalPopover` (new) |

The prop still defaults to `undefined`. Inside a Modal, the menu or
tooltip portals as before. `true` always portals, and `false` keeps
it in place.

A portalled menu or tooltip is no longer inside its container. CSS
that styles it as a descendant stops matching, and so do browser test
queries scoped to the container:

```css
/* stops matching when the menu portals */
.my-table .bx--list-box__menu { max-height: 10rem; }
```

Leave the container out of the selector, or keep the menu in place:

```svelte
<Dropdown portalMenu={false} … />
```

## 16. Component updates

Most of these components now follow v11 and need no code change,
but visual snapshots and some tests will change. SearchMenu needs a
change if you read its `value`.

### UserAvatar

`size="lg"` is 3rem (48px), not 2.5rem, with `heading-03` initials,
as in v11. In Gray 80, 90 and 100, the fills are one step lighter and
the initials use `text-inverse`, so they keep 5:1 contrast. In a
UserAvatarGroup, the ring between avatars takes the layer color
([#5025](https://github.com/carbon-design-system/carbon-components-svelte/pull/5025)).

### BigNumber

BigNumber follows v11's type scale. At the default size the value is
`heading-04`, not `heading-05`. The label is `label-01`
(`body-compact-01` at `xl`), and the total and percent sign step with
the value. The total uses `text-primary`
([#5026](https://github.com/carbon-design-system/carbon-components-svelte/pull/5026)).

`percentage` and `deltaPercentage` follow the locale's percent
pattern, so the sign takes the locale's place and spacing ("%12" in
Turkish, "12 %" in French). Percentages are no longer abbreviated: a
`value` of 1234.5 shows "1,234.5%", not "1.2K%"
([#5065](https://github.com/carbon-design-system/carbon-components-svelte/pull/5065)).

### InterstitialScreen

The title was an `h3`. It is now an `h1` in a full-screen takeover,
one level below an enclosing `Section`, and an `h2` in a modal
([#5027](https://github.com/carbon-design-system/carbon-components-svelte/pull/5027)).
Set `headingLevel` to fit your page outline:

```svelte
<InterstitialScreenHeader title="Welcome" headingLevel={2} />
```

The header and footer also match v11. A titled header sits on a
layer with a border, the progress indicator moves into the header,
and from `md` the Back, Next and Get Started buttons are 15rem wide.
The full-screen close button is a ghost button with a tooltip, named
by `iconDescription` as before.

### TagSet

The "+N" tooltip listed every hidden tag. With more than 10 hidden
tags, a click on "+N" now opens a View all modal of every tag, with a
search field
([#5028](https://github.com/carbon-design-system/carbon-components-svelte/pull/5028)).
`click:overflow` is now cancelable. Call `preventDefault()` in your
handler to keep the modal closed, or set `viewAllThreshold={Infinity}`
to turn View all off.

The new `overflowMode="popover"` lists the first 10 hidden tags and a
View all button. `overflowType` sets whether the hidden tags show as
text or as tags.

### ActionSet

ActionSet fills with the `layer` color, as v11 does, so a ghost action
no longer shows the page behind it. Actions that don't fill the row
sit at the inline end, with the primary in the corner
([#5029](https://github.com/carbon-design-system/carbon-components-svelte/pull/5029),
[#5030](https://github.com/carbon-design-system/carbon-components-svelte/pull/5030)).

The set now warns once per problem with `console.warn` when its
actions break v11's rules: more than one primary or ghost action,
more than four actions (three when stacked), a ghost action in a
stack with others, or a child that isn't a Button.

### SearchMenu

Picking an item now fills the field with the item's `text`. Before,
it wrote the item's `value`, so with ids as values the field showed
an id. `bind:value` and the value a form submits change with it
([#4807](https://github.com/carbon-design-system/carbon-components-svelte/pull/4807)). Read the item's value from the `select` event:

```svelte
<script>
  let value = "";
  let serviceId = "";
</script>

<SearchMenu bind:value on:select={(e) => (serviceId = e.detail.value)}>
  <SearchMenuItem text="Databases for TestSQL" value="svc-db-testsql" />
</SearchMenu>

<!-- before: value is "svc-db-testsql" -->
<!-- after: value is "Databases for TestSQL", serviceId is "svc-db-testsql" -->
```

## 17. Types

Some types are stricter, so `svelte-check` can flag code that passed
in 0.113.

- **Icon props take a component.** Every `icon` prop takes a Svelte
  component or `null`. A string such as `icon="Add"` rendered nothing
  and is now an error. Icons from `carbon-icons-svelte` fit on Svelte
  3, 4 and 5 ([#5127](https://github.com/carbon-design-system/carbon-components-svelte/pull/5127)).
- **HeaderSearch's `select` detail is a union.** It carries
  `selectedResult` for a result from `results`, or `item` for an item
  in the `menu` slot. Check which one before you read it
  ([#5129](https://github.com/carbon-design-system/carbon-components-svelte/pull/5129)):

  ```svelte
  <!-- before -->
  <HeaderSearch on:select={(e) => goto(e.detail.selectedResult.href)} />

  <!-- after -->
  <HeaderSearch
    on:select={(e) => {
      if ("selectedResult" in e.detail) goto(e.detail.selectedResult.href);
    }}
  />
  ```

- **String props take their real values.** A `kind` in Modal or
  ModalFooter `secondaryButtons` takes Button's kinds. TableHeader
  `scope` takes `"col"`, `"row"`, `"colgroup"` or `"rowgroup"`
  ([#5121](https://github.com/carbon-design-system/carbon-components-svelte/pull/5121)).
- **Slots and groups follow your data.** DataTable's
  `headerDecorator`, `rowDecorator`, `cellHeader` and `footerCell`
  slot props are typed by the row, not `any`. CheckboxGroup and
  ToggleButtonGroup infer their value type from `selected`, as
  RadioButtonGroup does, and their `change` detail follows it
  ([#5127](https://github.com/carbon-design-system/carbon-components-svelte/pull/5127)).
