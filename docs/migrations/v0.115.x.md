# Migrating to v0.115.x

0.115.0 raises the minimum browsers to the first versions with
`:has()`. Components that styled themselves by what they hold now read
it from the markup, so their server HTML is right before hydration.
Form fields put `class` and `style` on their root, Theme no longer
renders its own controls, and required fields show their own invalid
state instead of the browser's bubble.

Most of the changes are to defaults, not to types, so `svelte-check`
finds few of them. Run the codemod first: it makes the changes it can
and lists the rest with file and line. Then use the checklist and skip
any section that doesn't apply.

## Upgrade codemod

Install 0.115, then run the codemod from your app's root:

```sh
npx carbon-components-svelte-upgrade 0.115
```

It prints a diff and writes nothing. Run it again with `--write` to
apply the changes. It reads `.svelte`, `.svx`, `.js`, `.ts`, `.css` and
`.scss` files under `src`; pass other paths after the version. Markup
goes through your app's own `svelte/compiler`. Coming from 0.113? Leave
out the version: it reads the version you upgraded from and runs each
release's codemod in order.

| It rewrites | Section |
| :--- | :--- |
| A static Theme `render` to ThemeToggle, ThemeSelect or ThemeDropdown, bound to the same theme, with the `toggle`, `select` or `dropdown` props moved onto it | [3](#3-theme-controls) |
| Removes CardFooter `actionSet`, CardAction `iconOnly` and ListBoxMenuItem `hasLeftIcon` | [9](#9-card-and-list-boxes) |
| Removes ContentSwitcher `iconOnly` when every Switch sets `icon` | [11](#11-contentswitcher) |
| With `--keep-sizes`, adds `size="xl"` to a SearchMenu with no `size` | [6](#searchmenu-defaults-to-40px) |

At the end it lists what it leaves for you, by section. The Codemod
column in the table below says which changes it rewrites, which it
reports, and which it only names once per run because no file shows
them.

## Find what to change

Run this from your app's root. The codemod reports the same lines; use
these to check its work, or if you skip it.

```sh
# Form fields with a class or style. Check the CSS and queries that use it.
rg -n -U '<(TextInput|PasswordInput|TextArea|NumberInput|ComboBox|TimePicker|Search|TagInput|CopyInput|Select|DatePickerInput|MultiSelect|SearchMenu|FileUploaderButton)\b[^>]*\b(class|style)=' src

# Theme controls rendered through Theme.
rg -n -U '<Theme\b[^>]*\b(render|toggle|select|dropdown)=' src

# Defaults that changed: ComboBox name, required fields, SearchMenu size.
rg -n -U -e '<ComboBox\b[^>]*\bname=' -e '<SearchMenu\b' \
  -e '<(TextInput|Select|Checkbox|CheckboxGroup|RadioButtonGroup|TileGroup|DatePickerInput)\b[^>]*\brequired\b' src

# Layout, keyboard and motion: review each hit.
rg -n -e '<(InputGroup|TimePicker|ButtonSet|InlineNotification|ToastNotification|Dialog)\b' \
  -e 'datePickerType="simple"' -e 'shouldFilterRows' src

# Removed classes.
rg -n -e 'bx--card__header--actions' -e 'menu-item__option--icon-left' \
  -e 'bx--tabs--tall' -e 'nav-item--secondary-label' -e 'nav-link--single-line' \
  -e 'content-switcher--icon-only' \
  -e 'bx--(tile|card|modal|side-panel|checkbox-wrapper|radio-button-wrapper|checkbox-group|radio-button-group|text-input__field-wrapper|text-area__wrapper|number__input-wrapper|select-input__wrapper|date-picker-input__wrapper|list-box|data-table-header|table-sort__header|table-header-label)--decorator([^\w-]|$)' .

# Deprecated props.
rg -n -U -e '<CardFooter\b[^>]*\bactionSet' -e '<(CardAction|ContentSwitcher)\b[^>]*\biconOnly' \
  -e '\bhasLeftIcon\b' src
```

`svelte-check` flags the removed Theme props in typed code. The rest
build without error, so search for them.

## 1. Browsers

| Browser | 0.114 | 0.115 |
| :--- | :--- | :--- |
| Chrome, Edge | 87 | 105 |
| Firefox | 83 | 121 |
| Safari, iOS | 14.1 | 15.4 |

A rule that uses `:has()` drops whole in an older browser, so parts of
a component can lose their styles there. iPhones and iPads that can
update to iOS 15.4 keep working. If your users are on older browsers,
stay on 0.114 until they update.

The codemod names this once per run.

## 2. Form field class and style

A `class` or `style` on a form field now goes on the field's root
element. Before, most fields put it on the control: the `<input>`,
`<select>` or `<textarea>`. A margin on the control moved it away from
its icons, so the Select chevron and other icons dropped out of place
([#3136](https://github.com/carbon-design-system/carbon-components-svelte/issues/3136)).

The other rest props, such as `name`, `required`, `aria-*`, `data-*`
and `on:*`, stay on the control.

```svelte
<Select class="my-field" style="margin-bottom: 2rem" name="region" />
```

```html
<!-- 0.114 -->
<div class="bx--form-item">
  <div class="bx--select">
    <label class="bx--label">Region</label>
    <div class="bx--select-input__wrapper">
      <select class="bx--select-input my-field" style="margin-bottom: 2rem" name="region">…</select>
      <svg class="bx--select__arrow">…</svg>
    </div>
  </div>
</div>

<!-- 0.115 -->
<div class="bx--form-item my-field" style="margin-bottom: 2rem">
  <div class="bx--select">
    <label class="bx--label">Region</label>
    <div class="bx--select-input__wrapper">
      <select class="bx--select-input" name="region">…</select>
      <svg class="bx--select__arrow">…</svg>
    </div>
  </div>
</div>
```

### Components

| Component | 0.114 | 0.115 |
| :--- | :--- | :--- |
| TextInput, PasswordInput, TextArea, NumberInput, ComboBox, TimePicker, Search, TagInput, CopyInput | Control | Root |
| Select | `<select>` | Root |
| DatePickerInput | Input | `.bx--date-picker-container` |
| MultiSelect | List box field | Root |
| SearchMenu | Input | `.bx--search-menu` |
| FileUploaderButton | Hidden file input | Button |
| Dropdown, DatePicker, Slider, RangeSlider, Toggle, Checkbox, RadioButton, PinCodeInput, StarRating, InlineEdit | Root | Root, no change |

### What to change

| Use | 0.114 | 0.115 | Change needed |
| :--- | :--- | :--- | :--- |
| Layout: margin, grid area, flex | Breaks the icons | Moves the whole field | None |
| `style="width: 12rem"` | Narrows the control only. The label and helper text stay full width. | Narrows the whole field | None in most cases |
| Style the control | `.my-field { border-color: red }` | Matches the root | Add the element: `.my-field input` |
| Svelte scoped style | `:global(.x)` | Matches the root | `:global(.x input)` |
| Font on the control | `.mono { font-family: … }` | Carbon sets the font on the control, so it does not inherit from the root | `.mono input { font-family: … }` |
| Query the control | `querySelector(".my-field").value` | Returns the root `<div>`, so `.value` is `undefined` | `querySelector(".my-field input")`, or `bind:ref` |
| `name`, `required`, `aria-*`, `data-*`, `on:*` | On the control | On the control | None |

Use the element that matches the field:

| Component | Control selector |
| :--- | :--- |
| TextInput, PasswordInput, NumberInput, ComboBox, TimePicker, Search, TagInput, CopyInput, DatePickerInput, SearchMenu | `input` |
| TextArea | `textarea` |
| Select | `select` |
| MultiSelect | `.bx--list-box__field` |
| FileUploaderButton | None. The class now goes on the visible button. |

```svelte
<TextInput class="flagged" labelText="Email" />

<style>
  /* 0.114 */
  :global(.flagged) {
    border-bottom-color: var(--cds-support-error);
  }

  /* 0.115 */
  :global(.flagged input) {
    border-bottom-color: var(--cds-support-error);
  }
</style>
```

To reach the control in code, prefer `bind:ref`. It points at the
control in both versions.

The codemod reports each `class` and `style` on these fields, each rule
in the same file that uses such a class, and each compound selector
like `.bx--text-input.my-field`, which now matches nothing.

## 3. Theme controls

`Theme` rendered a toggle, select or dropdown through `render`, so every
page that used it shipped all three controls and their dependencies:
about 48.6 kB of JavaScript gzip for `<Theme persist />`, against
14.0 kB now. The controls are components of their own, bound to the
theme with `bind:theme`.

```diff
- <Theme render="toggle" toggle={{ size: "sm" }} />
+ <Theme bind:theme />
+ <ThemeToggle bind:theme size="sm" />
```

| 0.114 | 0.115 |
| :--- | :--- |
| `render="toggle"`, `toggle={{ ... }}` | `<ThemeToggle bind:theme ... />` |
| `render="select"`, `select={{ ... }}` | `<ThemeSelect bind:theme ... />` |
| `render="dropdown"`, `dropdown={{ ... }}` | `<ThemeDropdown bind:theme ... />` |

The props that went in `toggle`, `select` or `dropdown` go on the
control, including `themes`. The new controls label themselves:
ThemeToggle reads "Dark mode" with no "Off" and "On", and ThemeSelect
and ThemeDropdown read "Themes". Set `labelText` to keep another label.

The codemod rewrites a static `render`: it adds the control after
`Theme`, binds both to a `theme` variable (declaring one when `Theme`
has no binding) and moves the object's props onto the control. It notes
where the default labels change. A `render` set from an expression, or
a `Theme` whose `theme` is an expression, is reported.

## 4. ComboBox name

ComboBox put `name` on its text input, so a form received the item's
label, which need not be unique. `name` now submits `selectedId`
through a hidden input, like Dropdown: an empty string when nothing is
selected. Set `inputName` to submit the typed text too.

```svelte
<!-- 0.114: submits contact=Ada Lovelace -->
<ComboBox name="contact" {items} />

<!-- 0.115: submits contact=3, the selected item's id -->
<ComboBox name="contact" {items} />

<!-- 0.115: submits contact=3 and contact_text=Ada Lovelace -->
<ComboBox name="contact" inputName="contact_text" {items} />
```

To keep the 0.114 form data, move `name` to `inputName`. A new `form`
prop associates both inputs with a `<form>` elsewhere in the page.

The codemod reports each ComboBox with `name` and no `inputName`.

## 5. Required fields

A submit blocked by an empty required field showed the browser's
validation bubble. These fields now cancel the bubble, show their own
invalid state with `requiredInvalidText`, and focus the first such
field. Submission is still blocked, `required` stays on the control,
and `invalid` with `invalidText` still win.

| Component | Default `requiredInvalidText` | Focuses |
| :--- | :--- | :--- |
| TextInput | "Enter a value" | The input |
| Select | "Select an option" | The select |
| Checkbox | "Check this box to continue" | The box; inside a CheckboxGroup, the group reports instead |
| CheckboxGroup | "Select at least one option" | The first box |
| RadioButtonGroup | "Select an option" | The first radio button |
| TileGroup | "Select an option", below the tiles | The first tile |
| DatePickerInput | "Enter a date" | The input |

A simple DatePicker (`datePickerType="simple"`) also checks a typed
date against `dateFormat`. A date that doesn't match shows
`patternInvalidText`, "Enter a valid date", instead of the browser's
pattern message. DatePickerInput `required` is now a declared prop
rather than a rest prop.

```svelte
<!-- 0.114: the browser's bubble says "Please fill out this field." -->
<TextInput required labelText="Workspace" />

<!-- 0.115: the field shows "Name the workspace" and takes focus -->
<TextInput required requiredInvalidText="Name the workspace" labelText="Workspace" />
```

No change is needed unless you want other text or tests look for the
bubble. Tests that call `reportValidity()` or check `validationMessage`
should look for the field's invalid text instead.

The codemod reports each field with `required` and no
`requiredInvalidText` or `invalid`, and each simple DatePicker.

## 6. Sizes and layout

### SearchMenu defaults to 40px

A SearchMenu without `size` was 48px (`xl`), and its results menu
followed. It is now 40px (`lg`), like every other field, or the size of
the Form or InputGroup around it. ToolbarSearch keeps the toolbar's
height.

```svelte
<!-- 0.114: 48px -->
<SearchMenu {items} />

<!-- 0.115: keep 48px -->
<SearchMenu size="xl" {items} />
```

The codemod reports each SearchMenu with no `size`. Run it with
`--keep-sizes` to add `size="xl"` instead.

### InputGroup rows

Inside an InputGroup, Search and SearchMenu took the full row and
pushed their neighbours out, a DatePicker kept its fixed width, and
Dropdown, ComboBox and MultiSelect started from their content width.
Now all of them split the row evenly, each with `flex: 1 1 0`. Wrap a
field in a Box to fix its width.

```svelte
<InputGroup>
  <Search labelText="Search" />
  <Box width="16rem">
    <Dropdown labelText="Category" {items} />
  </Box>
</InputGroup>
```

An unsized ContentSwitcher, ToggleButtonGroup, OverflowMenu, MenuButton
or ComboButton kept its own height (32px or 40px) in every group. It
now follows the group: 24px in `xs`, 32px in `sm`, 48px in `xl`. A
default (40px) group is unchanged. Set `size` on the control to keep
the old height. ContentSwitcher and ToggleButtonGroup take `size="xs"`
now too.

The codemod reports each of these fields directly inside an InputGroup,
and each unsized control.

### TimePicker selects

TimePicker put Carbon's 2px margin on both sides of every select but
the last, so a lone select had no gap and others had 2px or 4px. Now
every select has 1px before it, the seam an InputGroup uses. No code
change is needed; expect it in visual tests. The codemod reports each
TimePicker that holds a TimePickerSelect.

### ButtonSet buttons

Buttons in a ButtonSet had `width: 100%` and `flex: 1 1 0`, so a set
that sized to its content gave every button the same width, and a
longer label could wrap. Each button now starts from its label
(`width: auto`, `flex: 1 1 auto`). Wide sets still reach the 196px cap,
and narrow sets still shrink. Stacked sets don't change. No code change
is needed; expect it in visual tests. The codemod reports each ButtonSet
without `stacked`.

## 7. Keyboard and motion

### Menus wrap

ArrowDown on the last item of Menu or ContextMenu, and ArrowUp on the
first, left focus where it was. Focus now wraps to the other end, as in
Dropdown and OverflowMenu. MenuButton and ComboButton open a Menu, so
they wrap too. Code that relied on the keys stopping must handle
`keydown` itself. The codemod names this once per run.

### Escape closes notifications

Escape closed only an `actionable` notification. It now closes any
InlineNotification or ToastNotification that shows a close button,
while focus is inside it. It goes through the same cancelable `close`
event as the close button, and the event's detail has a new `trigger`:
`"close-button"`, `"escape-key"` or `"timeout"`.

```svelte
<!-- 0.115: keep the 0.114 behavior -->
<InlineNotification closeOnEscape={false} title="Saved" />
```

The codemod reports each notification without `closeOnEscape`,
`actionable` or `hideCloseButton`.

### Dialog closes after its animation

Dialog now fades and slides like Modal. Closing by Escape, a backdrop
click, a `method="dialog"` form submit or `open={false}` called the
native `close()` at once, so the element's `open`, the bound
`open` and the `close` event changed in the same task. Now the dialog
stays open for up to 240 ms while it fades out, and then `open` turns
false and `close` fires. The new `close(value)` waits the same way.
Under `prefers-reduced-motion: reduce` it closes at once, as before.

```js
// 0.114
open = false;
expect(dialog).not.toHaveAttribute("open");

// 0.115: wait for the close event, or stub reduced motion in tests
open = false;
await waitFor(() => expect(dialog).not.toHaveAttribute("open"));
```

Code that reads the dialog right after closing it should run in the
`close` handler. The codemod reports each Dialog with `bind:open` or a
`close` handler.

## 8. DataTable with no results

A filter that matched no rows left an empty body. The table now
renders one row across every column with `noResultsText`, "No results",
or the `noResults` slot, and announces it. A table with no `rows` at all
renders nothing until you set `emptyText` or fill the `empty` slot.

```svelte
<!-- 0.115: keep an empty body -->
<DataTable {headers} {rows} noResultsText="">
  <Toolbar>
    <ToolbarContent>
      <ToolbarSearch shouldFilterRows />
    </ToolbarContent>
  </Toolbar>
</DataTable>
```

The codemod reports each DataTable that holds a filtering ToolbarSearch
and sets neither `noResultsText` nor the `noResults` slot.

## 9. Card and list boxes

`CardFooter` reads its `CardAction`s, and a `CardAction` reads an
icon-only button or OverflowMenu inside it. An option reads its left
icon. `CardFooter` `actionSet`, `CardAction` `iconOnly` and
`ListBoxMenuItem` `hasLeftIcon` still work but are deprecated: remove
them.

```diff
- <CardFooter actionSet>
-   <CardAction iconOnly>
+ <CardFooter>
+   <CardAction>
```

| Removed class | Select instead |
| :--- | :--- |
| `bx--card__header--actions` | `.bx--card__header:has(> .bx--card__actions)` |
| `bx--list-box__menu-item__option--icon-left` on Dropdown and ComboBox options | `.bx--list-box__menu-item__option:has(> .bx--list-box__menu-item__icon--left)` |

The codemod removes the three props and reports each use of the two
classes in markup, scripts and CSS.

## 10. Tabs

A tab set grows tall when CSS finds a secondary label in it, so the
server HTML is final. Three marker classes are gone, and a tab without
a secondary label no longer renders an empty one.

| Removed class | Select instead |
| :--- | :--- |
| `bx--tabs--tall` | `.bx--tabs:has(.bx--tabs__nav-item-secondary-label)` |
| `bx--tabs__nav-item--secondary-label` | `.bx--tabs__nav-item:has(.bx--tabs__nav-item-secondary-label)` |
| `bx--tabs__nav-link--single-line` | `.bx--tabs__nav-link:not(:has(> .bx--tabs__nav-item-label-wrapper))` |

```css
/* 0.114 */
.bx--tabs--tall { margin-block-end: 1rem; }

/* 0.115 */
.bx--tabs:has(.bx--tabs__nav-item-secondary-label) { margin-block-end: 1rem; }
```

The codemod reports each use of the three classes.

## 11. ContentSwitcher

A switcher whose switches all set `icon` fits them from the first
render, server HTML included. It no longer adds
`bx--content-switcher--icon-only` on its own. `iconOnly` still adds it
but is deprecated: remove it. CSS that targets the class should select
`.bx--content-switcher:has(> .bx--content-switcher-btn--icon)`.

```diff
- <ContentSwitcher iconOnly>
+ <ContentSwitcher>
    <Switch icon={Grid} text="Grid" />
    <Switch icon={List} text="List" />
  </ContentSwitcher>
```

The codemod removes `iconOnly` when every Switch inside sets `icon`. If
one doesn't, it leaves the prop and reports it, since the switcher would
stop fitting its switches. It reports each use of the class.

## 12. Decorator classes

A component with a filled `decorator` slot no longer adds a
`--decorator` class: the CSS finds the decorator element itself. CSS
that targets one of these classes should select the parent by its
decorator element, for example
`.bx--tile:has(> .bx--tile--inner-decorator)`.

| Component | Removed class |
| :--- | :--- |
| Tile, SelectableTile, RadioTile, ExpandableTile, ClickableTile | `bx--tile--decorator` |
| Card | `bx--card--decorator` |
| Modal, ComposedModal | `bx--modal--decorator` |
| SidePanel | `bx--side-panel--decorator` |
| Checkbox | `bx--checkbox-wrapper--decorator` |
| RadioButton | `bx--radio-button-wrapper--decorator` |
| CheckboxGroup | `bx--checkbox-group--decorator` |
| RadioButtonGroup | `bx--radio-button-group--decorator` |
| TextInput | `bx--text-input__field-wrapper--decorator` |
| TextArea | `bx--text-area__wrapper--decorator` |
| NumberInput | `bx--number__input-wrapper--decorator` |
| Select | `bx--select-input__wrapper--decorator` |
| DatePickerInput | `bx--date-picker-input__wrapper--decorator` |
| Dropdown, ComboBox, MultiSelect | `bx--list-box--decorator` |
| DataTable | `bx--data-table-header--decorator` |
| TableHeader | `bx--table-sort__header--decorator`, `bx--table-header-label--decorator` |

`bx--tile--decorator-rounded` stays, since the `rounded` prop sets it.

The codemod reports each use of these classes and names the selector
to use for each.

## New, not breaking

You don't need these to upgrade, but they may replace code you wrote
yourself.

- [Motion](https://svelte.carbondesignsystem.com/motion): a `transition`
